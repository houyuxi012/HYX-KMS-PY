# 产品可用性复审

本次已修复目录和脚本中发现的问题，并对全部展示产品执行本地检查。结果证明目录、协议实现和脚本生成在本地一致；没有真实 Windows / Office 设备，不能据此承诺每台设备均能成功激活。

## 全量覆盖

| 产品类型 | 展示条目 | 独立官方密钥复核 | 本地协议往返 | 脚本覆盖 |
| --- | ---: | ---: | --- | --- |
| Windows | 52 | 52 | 全部通过 | 全部通过 |
| Windows Server | 38 | 38 | 全部通过 | 全部通过 |
| Office | 83 | 68；另有 Office 2013 历史条目 15 个待补依据 | 全部通过 | 全部覆盖 x64 / x86 |
| 合计 | 173 | 158 已复核，15 个证据缺口 | 173 次通过 | 768 种组合通过 |

逐项结果见[产品可用性矩阵](产品可用性矩阵.csv)。协议检查使用各产品真实目录中的 App ID、SKU ID、Counted ID、v4/v5/v6 与计数阈值，校验响应的身份、协议版本、计数和间隔。它是本地请求编码、服务逻辑和响应验证，不是微软客户端验收。

768 种脚本组合覆盖每一个产品、Office 两种位数、域名 / IPv4 / IPv6、默认和自定义端口；检查密钥、脚本路径、命令参数、ASCII / CRLF 与错误退出分支。没有 Windows CMD 执行环境，不能把字符串断言等同于真实 BAT 执行。原有套件另有回环 TCP 和 TLS 检查。

## 修复内容

- 补齐 Windows Server 2022 Standard、Datacenter、Datacenter: Azure Edition 三个公开版本、协议标识及主机兼容映射。GVLK 以微软清单为准；协议标识按现用数据库上游核对，未整体导入上游目录。
- 新增 Server / Office 展示映射，使通用网页目录与范围更广的底层协议库分离。13 个未进入本次公开清单依据的专用或非通用条目移出选择器，底层原始数据保留。排除不等于判定该产品绝对无法激活，完整名称保存在 `activation_catalog.json` 的 `excluded` 中。
- Office 默认选择 LTSC Professional Plus 2024，Server 默认选择 2025 Standard，避免用户进入 Office 后默认安装 Access 的密钥；补充套件与单品选择说明。
- Office 未识别的年份停止生成，避免静默套用 Office16 路径；末尾 `/xpr` 或 `/dstatus` 返回非零时进入失败分支，避免误返回成功退出码。工具返回零也不能单独证明实际许可状态。
- Outlook、PowerPoint 的大小写名称统一；Windows、Server、Office 共享目录映射校验，缺失 SKU 或非法密钥会明确失败。

## 证据和剩余门禁

微软资料：

- [Windows / Windows Server GVLK](https://learn.microsoft.com/en-us/windows-server/get-started/kms-client-activation-keys)。
- [Office 2016 / 2019 / LTSC 2021 / 2024 GVLK](https://learn.microsoft.com/en-us/office/volume-license-activation/gvlks)。
- [Office 2010 官方历史 GVLK](https://learn.microsoft.com/en-us/previous-versions/office/office-2010/ee624355(v=office.14))。
- [Office 脚本路径和命令](https://learn.microsoft.com/en-us/office/volume-license-activation/tools-to-manage-volume-activation-of-office)。
- [现用数据库上游的协议标识](https://github.com/tfslabs/license-manager/blob/master/LmInternalDatabase.xml)。本次读取文件 SHA256 为 `e0d8d406f957afa7c6552f967a023f9cb15da1fd489951ef6c8ca05d291fd1f5`；只取 2022 三个目标条目的事实字段，密钥仍独立匹配微软资料。

Office 2013 历史官方链接本次返回 404，15 个条目保留原有协议库数据，不能标记为独立官方密钥复核通过。Office 2010 等旧版的密钥可核对不表示产品仍在支持期；明确需要旧版的组织应自行完成目标安装包、许可通道与实际运行验证。

真实设备门禁：每个部署所需版本均须核对安装版本和批量许可通道，在授权设备上运行并保留 Windows `/dlv`、`/xpr` 或 Office `/dstatus` 的脱敏证据。Azure Edition 另需验证目标环境条件。Office 应按实际安装位数测试；域名、IPv6、自定义端口须在实际网络验证。未执行的门禁在矩阵中统一标记为“未执行”。

## 重复验证

在项目的受控 Python 环境安装锁定依赖并准备 Node 后，从项目根目录运行：

```bash
python -B -W error -m unittest discover -s tests -v
node tests/test_activation.cjs
```

`test_product_matrix.py` 会遍历实际网页目录，调用 `test_product_matrix.cjs` 校验全部组合，并将当前产品密钥与独立官方资料快照对照。维护目录时必须同步审阅快照和矩阵，不能仅以 XML 自我对照代替外部依据。
