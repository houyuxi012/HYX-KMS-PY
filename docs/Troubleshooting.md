# 故障排查

先按「进程 → 端口 → DNS → 页面配置 → 产品与脚本」逐层定位。保留原配置和错误码，不要以重装系统、卸载现有密钥或关闭全部防火墙作为通用排障步骤。

## 网站 HTTPS 端口无法访问

- 检查是否使用完整镜像且设置 `SQLITE=true`。默认 `SQLITE=false` 只启动 KMS，精简镜像没有网站运行依赖。
- 旧镜像显示 `Restarting` 且日志出现 `/run/secrets/web-auth.json` 不存在时，说明实例仍依赖已取消的认证卷。停止旧容器，加载当前无认证版本并按[离线生产部署包](Offline-Deployment.md)重新启动；不要为新版本创建认证文件或认证卷。新版 `run.sh` 只在创建容器前预检 TLS，缺少或错误配置有效证书仍会拒绝启动。
- 检查日志和实际映射：`docker logs --tail 100 HYX-KMS-PY`、`docker port HYX-KMS-PY`。
- `run.sh` 默认使用 `127.0.0.1:443:8080`，只允许宿主机通过标准 HTTPS 端口访问。其他设备需要受控代理或正确的宿主机发布地址；端口被占用时可显式设置 `WEB_PUBLISH_PORT`。
- 容器内网站通常监听 `0.0.0.0:8080`；把 `WEB_HOST` 改为容器内 `127.0.0.1` 会影响 Docker 端口转发。
- KMS 或 Gunicorn 任一进程退出时，入口脚本会结束另一个进程；应从首次异常开始排查，不能只看容器处于 restarting。

## 页面仍显示 IP 或旧域名

`KMS_PUBLIC_HOST` 是网站默认值；未设置时浏览器取当前网站主机名。确认变量位于正在运行的容器中，重建使用新环境变量的容器并刷新页面。仅 `docker restart` 不会改变容器创建时的环境变量。

页面主机名不带协议和路径；外部端口填 `KMS_PUBLIC_PORT`。`IP`、`PORT` 是容器监听配置，与页面默认主机不是同一个概念。完整示例见[指定 KMS 域名](Getting%20Started.md#指定-kms-域名)。

## 域名可解析但客户端无法连接

在目标设备执行 `Resolve-DnsName kms.example.com` 和 `Test-NetConnection kms.example.com -Port 1688`。核对解析地址、来源网段路由、TCP 防火墙、NAT 转发、Docker 发布端口和 `KMS_ALLOWED_NETWORKS`。该白名单匹配 KMS 进程实际看到的来源；Docker/NAT 可能显示上游网关，不以客户端自报地址为准。外部端口与内部端口不同时，客户端使用外部端口。

HTTPS 网站能打开，不代表 KMS TCP 已通。只支持 HTTP 的域名代理不转发 KMS；IPv6 还需单独检查 AAAA、监听和路由。仅放通确实需要的来源与端口，不要全局关闭安全防护。

## 首页 500 或数据库记录不更新

- 独立运行网站时，确认 `PYKMS_SQLITE_DB_PATH` 指向服务端正在写入的同一个数据库，且网站账号有读取权限。网站不会自动创建缺失数据库。
- 完整镜像使用 `/data/HYX-KMS-PY_database.db`，服务账号 `hyx` 必须能写入 `/data`；从宿主机复制或恢复文件后需核对所有权。
- 端口探测不生成客户端记录。检查是否有实际协议请求、服务端是否启用 SQLite，以及首次数据库异常。
- 历史数据库可能与当前字段不兼容。先备份，再检查 Schema；不要直接删除数据库来隐藏错误。
- 新数据库不保存请求 IP，首页不再显示对应列。

`/livez` 仅表示网站进程存活；`/readyz` 在 HTTPS 下匿名开放，检查数据库和 RPC bind 响应，成功结果缓存 5 秒，但不验证完整协议或真实激活。健康端点 200 仍不能替代协议探测。

## Windows 或 Office 激活失败

保留完整错误码，核对已安装产品、版本、许可通道、所选 GVLK 和服务器地址。页面中的密钥不能将所有零售版或订阅版自动变为批量许可版本；产品匹配与使用授权需独立确认。

Office 架构按 **Office 本身的位数**选择。遇到 `OSPP.VBS` 找不到，核对实际安装路径、所选年份和 Office 是否支持该管理工具。Office 2016 及之后使用 `Office16`，有的安装带 `root` 目录。路径不符合内置候选时，应依据实际安装和官方工具说明处理，而不是从不明来源下载脚本。

脚本成功下载或模拟客户端往返通过，不等于目标设备激活成功。参照[验收层次](Usage.md#验收层次)查看设备端状态并保存脱敏结果。

## 产品列表或版本名称没有更新

确认修改的是当前入口使用的 `hyx_kms_py/` 数据，而非旧目录或构建产物。网站进程缓存产品目录；源码部署需重启网站，镜像部署需重建镜像并替换容器。XML、Windows 显示目录、官方快照各有职责，更新流程见[贡献说明](Contributing.md)。

## 提交问题时提供的信息

提供项目版本或目录快照、Python 与操作系统版本、部署方式、脱敏后的端口映射和相关配置、产品版本与架构、复现步骤、预期和实际结果、错误码及异常前后的日志。不要直接公开整个容器环境、机器标识、数据库、真实主机名、IP、个人信息或凭据。INFO/DEBUG 日志只在定位期间启用，并控制保存与访问范围。

## 网站返回400、403或503

HTTP 访问网站返回 400 是预期行为，浏览器必须改用 `https://`。403 通常来自宿主机防火墙、反向代理或上游 ACL，不是网站登录权限；当前网站不启用用户认证。`/readyz` 返回 503 时检查 `PYKMS_SQLITE_DB_PATH`、数据库读取、KMS 监听和 RPC bind；页面无需用户名、密码、Bearer 令牌或健康令牌。

## HTTPS 证书问题

网站必须用 `https://` 访问。启动报错时检查 `WEB_TLS_CERT_FILE`、`WEB_TLS_KEY_FILE` 绝对路径、PEM 格式、配对和服务账号读取权限；私钥权限必须 600，组内与其他用户不可读。健康检查失败时检查有效期、SAN 是否匹配 `WEB_TLS_SERVER_NAME`，以及系统或 `WEB_TLS_CA_FILE` 信任链。组织 CA 和自签名证书需要在客户端建立信任。轮换后重启网站进程。详见 [HTTPS 与本地证书](HTTPS.md)。
