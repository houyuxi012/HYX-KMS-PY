# 安全与交付整改

本文记录 2026-10-29 至 2026-11-01 的整改和当前验收边界，不替代真实设备、生产容量、恢复目标或许可审批。

## 协议与资源

- AESModeOfOperation 各实例独立持有 AES，防止 v5/v6 切换模式影响其他请求。
- TCP 按固定头与受限 frag_len 收齐；逐帧处理粘包、使用 sendall。单 PDU 上限 16384 字节；明确拒绝 RPC 分片、object UUID 和认证 trailer，未承诺完整 MS-RPCE 实现。
- 每连接只允许一次 bind 和一次激活，必须使用已接受的上下文和 op_num=0；不支持的协商不进入业务。
- 默认活动连接上限 64（KMS_MAX_CONNECTIONS，1..4096），单来源默认 16（KMS_MAX_CONNECTIONS_PER_SOURCE）。单次收发默认 5 秒（容器 KMS_IO_TIMEOUT），连接总期限默认 30 秒（KMS_CONNECTION_LIFETIME，不超过300秒）。全局或单来源超额立即关闭，不阻塞接受循环；停服关闭活动连接。单来源上限降低一个来源占满全部槽位的风险，不能替代网络 ACL。
- 严格 PKCS7、v4 请求/响应 hash、v5/v6 响应 hash、v6 HMAC 与 CMID/时间/版本关联校验。模拟器本身通过不代替独立协议向量或真实设备验收。
- 许可状态、客户端阈值和内外版本检查；未知协议返回二进制错误 stub，不再错误解码 UTF-8。

## 数据库

SQLITE=true 的审计为必需模式：数据库写入失败或新身份容量满时拒绝该次请求，保留日志，不伪装记录成功。默认 KMS_MAX_CLIENTS=10000；已有身份仍可更新。新身份创建预算持久化到 `identity_admission_budget`，跨 worker 和重启仍保留；全局默认每分钟 KMS_NEW_IDENTITY_PER_MIN=60，已知来源每分钟 KMS_NEW_IDENTITY_PER_SOURCE_PER_MIN=10，IPv6 来源按 `/64` 聚合；达到 80%、90% 容量各告警一次。容量满后使用 `scripts/archive_identities.py` 先预演、再显式确认归档；原记录、请求次数、操作人、原因和时间保存在 `identity_archive` / `identity_archive_manifest`，不会静默删除。机器名等文本日志在写入前用 JSON 转义控制字符，数据库保留原始值。

初始化在事务内创建身份唯一索引和最近请求索引；发现旧重复身份时，先将原表完整复制到 clients_before_identity_migration，再按最新记录合并并汇总请求次数。迁移幂等，任何异常回滚。数据库文件强制设为 0600，完整容器数据目录与日志分别设为 0700、0600；目录需要由容器 hyx 用户持有。旧库超额不截断；迁移备份表需要单独保留，不计入可新增记录容量。仍需在升级前备份整个数据库并在副本验证。

首页每页最多50条，稳定排序，统计由SQL聚合，页码受限；客户端声明的许可状态不是服务器认证后的资产证明。不会再显示未采集的来源IP列。

## 网站访问边界与健康

网站按部署要求对受控内网匿名开放，不启用用户登录、Basic 认证、认证文件、认证卷或健康检查 Bearer 令牌。所有页面仍强制 HTTPS，包括本机和 VPN 访问；HTTP 请求返回 400，不提供额外 HTTP 跳转端口。匿名开放不等于公网开放：部署者必须通过 `WEB_PUBLISH_ADDRESS`、宿主机防火墙、反向代理和上游 ACL 把 443 端口限制在获准内网。

页面和数据库包含客户端机器名、CMID、产品与请求统计。因为网站没有应用层用户身份，内网中的获准访问者可以看到这些记录。组织若要求用户级访问控制，应在反向代理或零信任网关实施，并把身份与审计留在该边界；当前应用不再维护另一套用户名和密码。

CSS 与 JavaScript 在 TLS 下匿名读取并缓存一天。动态页面响应使用 no-store，并包含 CSP、Permissions Policy、COOP、CORP、nosniff 和 frame deny；页面脚本已外置，JSON 数据块使用逐响应 nonce。

`/livez` 表示网站进程存活；`/readyz` 在 HTTPS 下匿名开放，检查现有数据库可读、clients 表、KMS 实际 RPC bind 响应及已接受的 NDR32 上下文，失败 503，成功结果缓存 5 秒。bind 成功仍不是完整激活协议或真实产品激活结果。完整镜像提供 Docker HEALTHCHECK。外部监控还应执行受控协议探测和告警，不把存活误作业务成功。

Gunicorn 使用单 worker、`gthread` 和默认 4 线程，`WEB_THREADS` 只能配置为 1..16。KMS 工作线程在最终进程确定后才启动，避免已创建线程后执行 daemon 双 fork；真实起停回归验证监听、连续探测、重复启动、状态查询、停止和残留进程/PID 清理。

## 备份、恢复与归档

`scripts/backup_database.py` 使用 SQLite 在线备份 API，生成完整性检查通过、包含 `clients` 表、行数一致、权限为 `0600` 的数据库及 SHA256 JSON 清单。`scripts/restore_database.py` 先验证清单和副本，要求显式确认停服，拒绝未确认的 SQLite sidecar，自动生成预恢复备份，再以同目录临时文件、完整性复检和原子替换完成恢复。

`scripts/archive_identities.py` 默认只预演符合保留期限的身份；`--confirm` 才在单一事务中保留原记录和请求计数并移出活动容量表。恢复和归档均已有测试覆盖，但生产演练、RPO/RTO、介质故障和不同历史 Schema 仍需目标环境验收。完整操作见[发布与运维](Operations.md)。

## 依赖、许可和发布

完整及精简依赖分别锁于 requirements.lock、requirements-minimal.lock，包含传递依赖和SHA256；Docker以require-hashes安装。基础镜像固定多架构索引digest。升级依赖需重新锁定、查询已知漏洞、回归与构建，不能仅改版本号。

VERSION 记录开发版本；发布仍须保存实际镜像digest和源码清单，不能把workspace当Git提交。旧构建hook不再下载即执行工具或重置宿主binfmt，发布hook要求显式registry目标；跨架构执行环境由管理员预先准备。

Bulma 0.9.4完整CSS与MIT正文随包交付，不再外部import。/license展示随附的第三方正文与来源清单。源码派生的精确上游修订、GUI和XML来源仍需维护者核实；材料已补齐不代表已通过商业分发法律审核。详见 hyx_kms_py/licenses/README.md。

## 必须单独完成的外部验收

1. 组织有授权的目标 Windows、Windows Server、Office 及两种Office位数，核对真实激活与续期结果。
2. 目标硬件上的并发、长期运行、容量和故障恢复，记录可用性目标与告警阈值。
3. 在升级副本验证迁移、还原与旧镜像回滚。当前未修改运行中的容器或真实数据库。
4. ARM各架构项目镜像实测、GUI实际图形环境验收、正式许可来源审阅。

这些项目没有被本地单元测试替代；未验证前不能宣称商业交付或高可用验收通过。
